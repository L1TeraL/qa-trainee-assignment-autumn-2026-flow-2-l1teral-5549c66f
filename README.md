## Что тестируется

Автоматизированные тесты покрывают основные сценарии работы API:

* регистрация пользователей;
* авторизация;
* получение и использование Bearer-токена;
* создание объявлений;
* получение объявления;
* получение списка объявлений продавца;
* получение статистики v1;
* получение статистики v2;
* удаление объявлений;
* проверка доступа к защищённым endpoint'ам;
* проверка некорректных входных данных;
* негативные сценарии;
* проверка UUID;
* проверка уникальности идентификаторов;
* проверка граничных значений;
* полный E2E-сценарий жизненного цикла объявления.

Подробный набор тест-кейсов находится в `TESTCASES.md`.

## Установка

Клонировать репозиторий и перейти в директорию проекта:

```bash
git clone <repository-url>
cd qa-api-tests
```

Создать виртуальное окружение:

```bash
python3 -m venv .venv
```

Активировать виртуальное окружение:

```bash
source .venv/bin/activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

## Запуск тестов

Запустить все тесты:

```bash
pytest -v
```

Запустить отдельный набор тестов:

```bash
pytest -v tests/test_registration.py
```

```bash
pytest -v tests/test_items.py
```

Запустить E2E-сценарий:

```bash
pytest -v tests/test_e2e.py
```

## Результаты тестирования

Последний полный запуск:

```text
55 tests collected
53 passed
2 failed
```

Два падающих теста являются ожидаемым результатом проверки найденных дефектов API:

* `test_create_item_with_negative_price` — API позволяет создать объявление с отрицательной ценой;
* `test_create_item_with_negative_statistics` — API позволяет создать объявление с отрицательными значениями статистики.

Тесты намеренно оставлены с ожидаемым статусом `400`, поэтому они продолжают фиксировать дефекты до их исправления.

Подробное описание найденных дефектов находится в `BUGS.md`.

## Allure

Проект использует `allure-pytest` для формирования тестовых отчётов.

При запуске:

```bash
pytest -v
```

результаты сохраняются в директорию:

```text
allure-results/
```

Для запуска интерактивного отчёта:

```bash
allure serve allure-results
```

Отчёт позволяет просматривать:

* результаты выполнения тестов;
* длительность тестов;
* отдельные шаги;
* assertions;
* информацию об ошибках;
* attachments.

Скриншоты отчёта находятся в директории `docs/`.

## Тестовые данные и фикстуры

Для регистрации используются динамически генерируемые usernames на основе UUID. Это позволяет повторно запускать тесты без конфликтов с уже существующими пользователями.

Необходимые данные для авторизации и создания объявлений подготавливаются с помощью pytest fixtures.

Созданные объявления удаляются после выполнения тестов, где это возможно.

## Независимость тестов

Тесты не должны зависеть от порядка выполнения.

Каждый тест самостоятельно подготавливает необходимые данные либо использует соответствующие pytest fixtures.

Для защищённых endpoint'ов используется Bearer-токен, полученный через:

```text
POST /api/1/autorize
```

## E2E-сценарий

В проекте реализован полный жизненный цикл объявления:

```text
Регистрация
    ↓
Авторизация
    ↓
Создание объявления
    ↓
Получение объявления
    ↓
Получение статистики v1
    ↓
Получение статистики v2
    ↓
Удаление объявления
    ↓
Проверка удаления
```

E2E-тест проверяет взаимодействие основных API-операций в рамках одного пользовательского сценария.

## Ruff

Для статического анализа и форматирования Python-кода используется Ruff.

Проверка кода:

```bash
ruff check .
```

Проверка форматирования:

```bash
ruff format --check .
```

Автоматическое форматирование:

```bash
ruff format .
```

В проекте включены проверки:

* `E` — ошибки стиля;
* `F` — потенциальные ошибки и проблемы Python-кода;
* `I` — сортировка и организация импортов.

Основные настройки Ruff находятся в `pyproject.toml`.

## Проверка перед отправкой

Перед сдачей задания рекомендуется выполнить:

```bash
ruff check .
ruff format --check .
rm -rf allure-results
pytest -v
```

Ожидаемый результат текущего состояния проекта:

```text
53 passed
2 failed
```

Два failed-теста соответствуют дефектам, описанным в `BUGS.md`.
